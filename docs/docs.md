# docs.md - A/B 테스트 성과 대시보드 생성 지침서 (범용 표준 템플릿)

## 1. 역할 및 목적 (AI 에이전트)
당신은 모바일 앱 및 디지털 플랫폼의 행동 로그 데이터를 기반으로 **프로덕트 매니지먼트(PM) 및 그로스(Growth) 분석 대시보드 HTML**을 자동으로 생성하는 전문 AI 데이터 에이전트다.

* **핵심 역할**:
  - 원천 고객 행동 로그(Event Log)를 분석하여 A/B 테스트 가설 검증의 인과관계를 입증하고, 경영진과 실무진이 즉시 납득할 수 있는 **최고급 인터랙티브 웹 대시보드**를 구현한다.
* **범용 템플릿 원칙**:
  - 본 지침서는 특정 기업(패스오더)에만 종속되지 않으며, **어떤 서비스(커머스, 배달, 핀테크, 구독 서비스, O2O 등)의 A/B 테스트 데이터가 들어오더라도 동일한 분석 규격과 높은 완성도로 대시보드를 재생성**할 수 있는 범용 프레임워크를 제공한다.
  - *(현재 기본 레퍼런스 데이터: 패스오더 90일 교차 브랜드 통합 적립 A/B 테스트 로그)*

---

## 2. 프로젝트 핵심 목적
1. **비즈니스 가설 검증의 정량화**:
   - 새로운 기능/제도(예: 교차 통합 적립, 구독제, 신규 온보딩 등)가 기존 방식 대비 **고객 잔존율(Retention), 방문 빈도(DAU/세션), 구매 빈도(Frequency)**를 실제로 개선했는지 통계적으로 증명한다.
2. **락인(Lock-in) vs 신기 효과(Novelty Effect) 분리**:
   - 일시적 호기심에 의한 초기 반짝 상승(1~2주)과 습관화에 의한 **장기 리텐션 평탄화(Flattening, 8~12주)**를 명확히 구분하여 보여준다.
3. **직관적인 의사결정 지원**:
   - 복잡한 원천 로그를 5대 핵심 KPI, 코호트 리텐션 히트맵, 행동 퍼널 전이 차트로 시각화하여 비전문가도 0.5초 만에 성과를 직관적으로 이해할 수 있게 한다.

---

## 3. 반드시 지켜야 할 개발 원칙
1. **데스크톱 우선의 독립 단일 파일 (Standalone HTML)**:
   - 외부 웹 서버나 DB 연결 없이, 브라우저에서 더블클릭만으로 즉시 구동되는 단일 HTML 파일(`output/passorder_dashboard.html`)로 생성한다.
2. **동적 데이터 집계 (하드코딩 절대 금지)**:
   - 모든 KPI, 일자별 DAU, 주차별 잔존율, 퍼널 단계 수치는 `data/*.csv`로부터 Python 스크립트를 통해 계산되어 템플릿에 동적으로 바인딩되어야 한다.
3. **엄격한 30분 세션 규칙 (Sessionization)**:
   - 모바일 앱 표준에 따라 마지막 행동 이후 30분 이상 비활성화 시 새로운 `session_id`로 분리하여 세션 수를 정밀 집계한다.
4. **글자 줄바꿈 원천 차단 (No-Wrap Data Table)**:
   - 표 내부의 주차, 수치, 퍼센트 텍스트가 다음 줄로 줄바꿈되어 깨지는 현상을 방지하기 위해 모든 셀에 `white-space: nowrap`을 강제한다.
5. **막대 상단 수치 표기 (Direct Value Labels)**:
   - 핵심 비교 차트는 마우스 호버에만 의존하지 않고, **막대 최상단에 실제 수치(82.9%, 90.8% 등)가 흰색 볼드로 상시 표기**되도록 구현한다.

## 4. 입력 데이터 표준 규격 (Input Data Schema)

대시보드 생성을 위해 `data/*.csv` 파일은 다음의 표준 컬럼 구조를 갖춘다. 새로운 도메인의 데이터를 적용할 때도 아래 규격에 매핑하면 동일하게 작동한다.

### 4.1 필수 컬럼 (Core Columns)

| 컬럼명 | 데이터 타입 | 필수 여부 | 설명 및 데이터 기준 |
| :--- | :---: | :---: | :--- |
| `event_time` | DATETIME | 필수 | 행동 발생 일시 (`YYYY-MM-DD HH:MM:SS` 형식, 시계열 및 코호트 기준) |
| `user_id` | STRING | 필수 | 고객 고유 식별자 (중복 제거 DAU 및 유저당 지표 산출 기준) |
| `session_id` | STRING | 필수 | 30분 타임아웃 규칙이 적용된 접속 세션 고유 번호 |
| `order_id` | STRING | Nullable | 구매/결제 완료 시 발급되는 주문 식별자 (미주문 이벤트는 Null/빈값) |
| `event_name` | STRING | 필수 | 고객 행동 유형 (`app_open`, `add_to_cart`, `purchase` 등 퍼널 단계) |
| `ab_test_group`| STRING | 필수 | 실험군/대조군 구분 (`Group A (Control)` vs `Group B (Treatment)`) |
| `is_cross_brand_order` | BINARY | 필수 | 핵심 가설 행동 발생 여부 (`1`: 교차/신규 이용, `0`: 단일/기존 이용) |

### 4.2 권장 및 확장 컬럼 (Domain & Financial Extensions)

| 컬럼명 | 데이터 타입 | 용도 및 예시 |
| :--- | :---: | :--- |
| `cafe_brand` / `category` | STRING | 매장 브랜드명 또는 서비스 카테고리명 (점유율 및 교차 이용 분석) |
| `cafe_id` / `store_id` | STRING | 개별 지점 식별자 (동일 브랜드 타 지점과 교차 브랜드를 명확히 분리) |
| `payment_amount` | INTEGER | 실 결제 금액 또는 장바구니 담기 금액 (GMV 및 객단가 산출) |
| `available_reward_point` | INTEGER | 해당 이벤트 시점 고객의 보유 포인트/충전금 잔액 |
| `earned_reward_point` | INTEGER | 결제 시 신규 적립된 포인트 (혜택 제공액 추적) |
| `used_reward_point` | INTEGER | 결제 시 차감 사용한 포인트 (할인 체감 여부 확인) |

## 5. 5대 핵심 KPI 정의 및 산출 수식

대시보드 상단 5개 주황색 카드에 배치되는 표준 핵심 지표:

1. **일일 활성 사용자 수 (평균 DAU)**:
   $$\text{Average DAU} = \frac{1}{N \text{일}} \sum_{t=1}^{N} \text{Distinct}(user\_id)_t$$
   *(유저가 하루에 10번 접속해도 해당 일자 카운트는 '1명'으로 중복 제거)*
2. **유저 1인당 평균 방문 세션 수 (Avg Sessions per User)**:
   $$\text{Sessions per User} = \frac{\text{전체 고유 } session\_id \text{ 수}}{\text{해당 그룹 총 유저 수}}$$
3. **유저 1인당 구매 빈도 (Orders per User)**:
   $$\text{Orders per User} = \frac{event\_name = \text{'purchase'인 고유 } order\_id \text{ 수}}{\text{해당 그룹 총 유저 수}}$$
4. **교차 브랜드 / 타겟 행동 전환율 (Cross-Brand Ordering Rate)**:
   $$\text{Cross Rate (\%)} = \frac{\text{전체 구매 중 } is\_cross\_brand\_order = 1\text{인 주문 수}}{\text{전체 구매 주문 수}} \times 100\%$$
5. **결제 최종 전환율 (Checkout CVR)**:
   $$\text{Checkout CVR (\%)} = \frac{\text{결제 완료(purchase) 건수}}{\text{결제 수단 확인(choose\_payment\_methods) 건수}} \times 100\%$$

## 6. 권장 화면 구조 (Layout Architecture)

대시보드는 다음의 표준 4단 구조로 배치한다:

```
[1단: 상단 헤더]
  - 좌측: 브랜드 공식 로고 (예: '패스'(흰색) + '오더'(주황색)) + 프로젝트 타이틀
  - 우측: 대조군 A (🏪 단일 스탬프 ❌) vs 실험군 B (☕ 통합 적립 ⭕) 미니 카드

[2단: 5대 핵심 KPI 그리드]
  - 5개 독립 카드: 주황색 그라데이션 배경 + 순백색 볼드 텍스트 + 대조군 대비 Lift 알약 배지

[3단: 네비게이션 탭 (3 Tabs)]
  - 📈 1. 가설 검증 & 코호트 리텐션
  - 🛒 2. 14단계 행동 퍼널 분석
  - ☕ 3. 교차 브랜드 이용 분석

[4단: 탭별 메인 컨텐츠 영역]
  - Tab 1: 90일 리텐션 곡선 라인차트(기간 메모 상자 포함) + 주차별 잔존율 표(No-Wrap) + DAU 시계열
  - Tab 2: 14단계 퍼널 수평 바차트 + 핵심 4대 구간 세로 막대그래프(막대 위 수치 상시 표기)
  - Tab 3: 6대 브랜드 주문 건수 분포 바차트 + 리워드 포인트 누적/소진 사이클 통계
```

## 7. 디자인 시스템 및 시각 스타일

* **테마**: 패스오더 공식 비즈니스 사이트 기반 **풀 다크 테마(Full Dark Theme)**.
* **배경색**: `--bg-dark-root: #0A0C10` (Deep Black), 카드 서피스: `#181B26`.
* **주조색 (Accent)**: 패스오더 오렌지 `--po-orange: #FF5C1E` / `#FF6525`.
* **KPI 카드**: `background: linear-gradient(135deg, #FF6525 0%, #FF4500 100%); color: #FFFFFF;`
* **폰트**: 한글 UI는 `Pretendard`, 영문/숫자는 `Outfit` (모던 지오메트릭 폰트).
* **차트 스타일**: Chart.js 기반 다크 그리드(`color: #1E2230`), 부드러운 라인 텐션(`0.25`), 둥근 막대 모서리(`borderRadius: 6`).

## 8. 대시보드 검증 및 성공 기준 (Quality Gates)

대시보드 생성 후 반드시 다음 4가지 검증을 통과해야 배포 완료로 간주한다:

1. **지표 일치성 검증 (Data Integrity)**:
   - Python 계산 스크립트로 도출된 5대 KPI 및 주차별 잔존율 수치와 HTML 대시보드 내 표기 수치가 100% 일치해야 함.
2. **차트 렌더링 무결성 (Zero Errors)**:
   - 브라우저 콘솔 창에 JavaScript 에러가 0건이어야 하며, 3개 탭 전환 시 모든 차트가 리사이징 깨짐 없이 매끄럽게 렌더링되어야 함.
3. **세로 막대 위 수치 표기 확인**:
   - 퍼널 핵심 구간 전환율 차트 막대 상단에 `82.9%`, `90.8%` 등의 수치가 정확히 렌더링되는지 확인.
4. **줄바꿈 검증 (No-Wrap)**:
   - 브라우저 창 크기를 줄여도 주차별 잔존율 표 내부 텍스트가 줄바꿈되지 않고 온전한 형태를 유지하는지 확인.
